# Codex setup

From the repository root Codex discovers `AGENTS.md`, `.codex/config.toml`, `.codex/rules/*.rules`,
and `.agents/skills/<name>/`.

```bash
codex
```

Verify:

1. Trust the repository when asked. **Without trust Codex ignores `.codex/config.toml` and the
   command rules**, including the rule forbidding `git push`.
2. Run `tools/check-agent-setup`; it also checks the rules with `codex execpolicy check`.
3. Ask: "Summarize the instruction sources you loaded and list the available skills."
4. Confirm `$kickoff`, `$writespec` and `$speccheck` appear in `/skills`.

## Command rules

`.codex/rules/kit.rules` is generated by the agent kit from its permission list; project rules go in
another file in the same folder. Rules are prefix matches with no wildcards, so a command shape like
`git -C <path> push` cannot be forbidden by a rule; `AGENTS.md` forbids it instead. Test a command
with:

```bash
codex execpolicy check --rules .codex/rules/kit.rules -- git push origin main
```

When you approve a command with "don't ask again", Codex writes a permanent rule to
`~/.codex/rules/default.rules` that applies in every repository. Review that file occasionally.
